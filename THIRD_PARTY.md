# Third-party software

The repository's MIT license applies to Driftverk code. Dependencies, bundled tools, fonts, operating-system packages, and container base images keep their upstream licenses. An SPDX license label or an SBOM does not replace their license text, copyright notices, source obligations, or commercial terms.

## Source publication and image distribution

A source-only repository release contains Driftverk source, build recipes, and the explicitly included upstream license supplements. Dockerfiles describe downloads performed during a build; publishing those recipes does not itself distribute the downloaded binary images or tools. The source release does not place those external components under MIT or certify an independently built image for redistribution.

Distributing built browser assets, CLI binaries, or container images is a separate distribution of the components they contain. Keep their required notices and license texts with them. For images containing copyleft binaries, provide the corresponding source and build material required by each component's license for the actual versions distributed, including base-image packages. Identify release materials by image digest and architecture. SBOM and notice archives support that review but do not replace corresponding source or establish permission to redistribute proprietary components. See [the GNU distribution FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#UnchangedJustBinary) and [GPLv3's object-code distribution requirements](https://www.gnu.org/licenses/gpl-3.0.html#section6).

## Generated notices

- `sh cli/build.sh` produces `control-plane/installer/bin/THIRD_PARTY_NOTICES.txt` beside the six CLI binaries and checksums. Distribute that file and the copied Driftverk `LICENSE` with every CLI binary. It contains Go runtime terms and the upstream license, notice, copyright, and patent files for all modules in the build list. The module inventory can include dependencies used only on another supported operating system.
- `npm --prefix control-plane run build` produces `control-plane/dist/public/third-party-notices.txt`. Keep it with the browser assets. It includes the installed production dependency inventory, including server packages, and actual upstream legal files or upstream README text where that is the published notice.
- The SSH gateway image contains `/usr/share/driftverk/THIRD_PARTY_NOTICES.txt`, generated from its Go build list. The control-plane image contains the equivalent installed npm dependency notices, plus the browser and CLI notice files.
- CI generates an SPDX JSON SBOM for each built control-plane, Compute agent, SSH gateway, and data gateway image. The development-image workflow generates separate inventories for AMD64 and ARM64. Published development images request BuildKit SBOM and provenance attestations.
- CI also exports installed legal files to image-specific tar archives with `scripts/third-party-image.sh`. Development-image archives include Debian copyright files and their shared license texts, installed global npm legal files, and Python legal files. Documentation symlinks are followed so the archive contains the referenced text. Keep those archives and inventories with the corresponding image digest when distributing images.

The image archives preserve what the installed image supplies. They are not a claim that every upstream notice or corresponding source archive is present. SBOM generation is an inventory step, not a vulnerability scan or legal clearance. The development-image verification job and publish job build separately; retain the published digest's attestation when assessing the actual release.

## Component terms and image scope

The browser and control-plane npm dependency tree includes MIT, ISC, BSD, and Apache-2.0 components. See the generated file for each version's actual terms. The CLI includes Go and `golang.org/x/*` BSD terms, MIT-licensed keyring and flag packages, and D-Bus dependency terms. The Go SSH gateway includes Go, `golang.org/x/*`, and Gorilla WebSocket BSD terms.

The development image includes Debian packages and Chromium, Git, Docker Engine, containerd, Docker Compose, Buildx, Tailscale, noVNC, FFmpeg, fonts, Node.js, Python, Bun, pnpm, uv, OpenAI Codex, and Claude Code. These have different licenses, including copyleft licenses and bundled dependency notices. `/usr/share/doc/*/copyright`, tool-supplied license files, and the built image's inventory are the starting points for a distribution review. Redistributing a copyleft binary may require corresponding source and build material; exporting notices alone does not meet that requirement. Base images and globally installed tools are in scope even when no source code for them appears in this repository.

OpenAI Codex is a separate Apache-2.0 project, with its own notices and bundled components. API accounts, authentication, and service terms remain separate from the software license. See [the upstream Codex repository](https://github.com/openai/codex).

Claude Code is proprietary. The pinned `@anthropic-ai/claude-code@2.1.263` package states that Anthropic reserves all rights and links to [Claude Code legal agreements](https://code.claude.com/docs/en/legal-and-compliance). Those agreements allow preinstalling or running Claude Code in hosted environments subject to Anthropic's Commercial Terms and stated conditions. Keep the binary unmodified, preserve all built-in authentication methods, and have every end user authenticate with their own credentials and pay their provider directly. Do not resell or intermediate usage. Anthropic's product name and trademark restrictions also apply. Its inclusion in `images/dev/Dockerfile` does not put it under Driftverk's MIT license. Check that the distribution and service satisfy these conditions before publishing the image, or produce a variant without Claude Code.
